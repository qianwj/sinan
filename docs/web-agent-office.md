# Web 体验层设计：虚拟 Agent 办公室

> **文档性质**：体验与注意力层（[`architecture.md`](architecture.md) §3.1、§5.1）UI 设计的概念与交互基线。
> **覆盖**：虚拟 agent-office 的隐喻、空间模型、信息架构、状态语言、交互边界、实时数据订阅、失败与降级。
> **不覆盖**：具体前端框架、CSS、组件库、HTTP 路由、SSE 实现、像素级设计。
> **基线**：[`requirements.md`](requirements.md) v0.1、[`architecture.md`](architecture.md) v0.1、[`actor-runtime.md`](actor-runtime.md) v0.2。
> **版本**：v0.3 ｜ **状态**：评审中（D-05 最小化拟人化例外已落，等待 v0.4 复核） ｜ **更新**：2026-09-06

## 1. 文档规则

1. 体验层是只读派生视图（`architecture.md` §5.1 职责）。本文档不得引入写领域事实的入口。
2. 每个 UI 表面必须回指一个或多个 `REQ-*` / `NFR-*` ID；纯装饰元素不进入基线。
3. 视觉隐喻只是认知辅助；它不增加新的领域语义。任何状态仍须能在 actor 状态机中精确定义。
4. 当 UI 与领域状态发生冲突时，以领域状态为准；UI 必须可被 server 状态重建。
5. 任何"美观但会牺牲可解释性/可控性/性能"的设计选择被拒绝（`NFR-01`、`NFR-02`、`NFR-06`）。
6. 本文不指定框架、库、像素或色值，只规定体验必须满足的约束。

## 2. 体验目标

虚拟 agent-office 是单人产品所有者与 AI agent 团队协作的"现场"。它要回答的核心问题只有四个：

1. **我现在需要判断什么？** —— 注意力路由（`REQ-ATT-01`）
2. **谁在做什么，做到了哪一步？** —— 工位视图（`architecture.md` §3.1）
3. **刚才发生了什么？** —— 事件与状态变化流（`REQ-REC-05`）
4. **我接下来可以做什么、不能做什么？** —— 边界可见（`NFR-01`）

不是问题的事，UI 不主动呈现。

### 2.1 成功标准

| 维度 | 定义 | 主要锚点 |
|---|---|---|
| **注意力经济** | 打开 UI 后 30 秒内能看到所有未解决阻塞项 | `REQ-ATT-01`、`REQ-ATT-03` |
| **可解释** | 任一状态、排序或推荐都能链接到事实、规则或先例 | `NFR-02`、`REQ-ATT-02` |
| **不阻塞** | 任意 agent 操作（长任务、模型调用、检索）都不能阻塞注意力界面 | `NFR-06` |
| **可恢复** | UI 可丢弃：刷新或崩溃后能根据 server 状态重建，不丢事实 | `REQ-REC-01`、`architecture.md` §9.1 |
| **人类权威可见** | 任何改变目标/范围/交付/外部副作用的动作都先停在 UI 上等人确认 | `NFR-01`、`REQ-ATT-04` |

## 3. 隐喻与边界

### 3.1 为什么是办公室

Sinan 的核心是一人带一支 AI 团队。办公室这个隐喻承载三件领域里已经存在的事：

- **工位 = actor**：每个 agent 是一个有持久身份、角色、状态的实体。办公室让人一眼看出"团队由谁组成"。
- **现场感 ≠ 日志**：原始 agent 日志是证据但不是体验（`architecture.md` §5.1 "原始 agent 日志可以作为证据，但不能是唯一解释"）。办公室把日志重新组织成"他在做什么"的现场视图。
- **可达性 ≠ 聊天**：用户不是和 agent 聊天；用户是到工位旁看一眼。UI 应支持"走过去看一眼"的低摩擦交互。

### 3.2 隐喻不做什么（反向约束）

- **不暗示 agent 之间有横向通信**：agent 之间不直接交流，它们都和黑板/任务协作层交互（`architecture.md` §3.2）。办公室不要让用户产生"agent 在等你走过去"的期待。
- **不暗示 agent 有情绪或意图**：状态变化来自 manager，不是 agent 的"心情"。
- **不暗示"全员开会"**：没有"全员同步"的中心事件，决策只走决策入口。
- **不暗示动画角色等同于进行中**：UI 动画必须能被关闭；状态来自持久化事件而非前端模拟。

### 3.3 体验层与领域层的关系

```text
┌────────────────────────────────────────────────────────────────┐
│ 虚拟 agent-office（体验层，只读派生视图）                      │
│                                                                │
│  ┌──────────────┐   ┌──────────────────┐   ┌───────────────┐    │
│  │ 决策收件箱   │   │ 工位视图（办公室）│   │ 事件 / 历史    │    │
│  └──────────────┘   └──────────────────┘   └───────────────┘    │
│         │                   │                     │             │
│         └──── 派生读模型 ───┴──── 派生读模型 ──────┘             │
│                            ▲                                    │
└────────────────────────────│────────────────────────────────────┘
                             │ 事件订阅 + 派生查询
                             │
┌────────────────────────────│────────────────────────────────────┐
│ 治理 / 协作 / 记忆 / 可靠性层（领域层）                         │
│                                                                │
│  意图 / 需求 / 任务 / 决策 / 先例 / 交付 ──▶ 事实事件 ──▶ 持久化│
└────────────────────────────────────────────────────────────────┘
```

UI 永远不直接写领域事实（`architecture.md` §5.1 "不负责：...改变领域状态"）。用户操作经过命令边界回到领域层，再以事件流回到 UI。

## 4. 信息架构

整体按"注意力密度"分三个区域。任何屏幕尺寸下至少呈现前三块：

### 4.1 顶部注意力带（永远在）

**目的**：不滚动就能看到"现在是否需要我"。

**元素**：

- 决策收件箱计数（按阻塞成本排序的前 N 项可展开 — `REQ-ATT-03`）；
- 当前焦点路径（已打开的决策 / 需求 / 任务）；
- 异常指示（`quarantined` actor 或恢复异常时持续可见 — `REQ-REC-05`、`architecture.md` §7.7）；
- 同步状态（与 server 的连接；失联时降级显示 — 见 §10）。

**不展示**：未读 agent 日志数、未完成任务总数（上下文噪声 — `REQ-ATT-03`）。

### 4.2 中央工位视图（虚拟办公室）

主区域，是隐喻的承重墙。

#### 4.2.1 布局示意

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 决策收件箱 [2]   焦点：需求 R-12 / 任务 #456 / 决策 #789   ●已同步  │ ← §4.1
├─────────────────────────────────────────────────────────────────────┤
│ 正在工作（running）                                                │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐                           │
│  │ dev-1    │  │ pm-1     │  │ qa-1     │                           │
│  │ 后端工程 │  │ 产品     │  │ 测试     │                           │
│  │ ▶ 任务   │  │ ▶ 任务   │  │ ▶ 任务   │                           │
│  │ #456    │  │ #460    │  │ #461    │                           │
│  └──────────┘  └──────────┘  └──────────┘                           │
│                                                                     │
│ 待命中（ready / created / 无授权暂停）                              │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐                           │
│  │ des-1    │  │ devops-1 │  │ ...      │                           │
│  └──────────┘  └──────────┘  └──────────┘                           │
│                                                                     │
│ 需介入（failed / quarantined / 用户暂停）                           │
│  ┌──────────┐                                                      │
│  │ dev-2  ⚠ │ ← quarantined：租约过期 + 副作用未知，等你判断       │
│  └──────────┘                                                      │
├─────────────────────────────────────────────────────────────────────┤
│ [事件流]  [需求版本]  [交付摘要]  [先例与记忆]   ← 折叠侧栏（§4.3）  │
└─────────────────────────────────────────────────────────────────────┘
```

#### 4.2.2 布局原则

| 原则 | 说明 |
|---|---|
| **分状态分群** | 工位按"当前 actor 状态机状态"分群，不是按角色或 worktree（见 §5.2）。 |
| **稳定位置** | 工位在跨刷新、跨设备之间位置一致（持久化于 server，详见 §5.5）；身份色来自 `role`；状态变化移动卡片而非闪烁（`NFR-02`）。 |
| **可压缩** | 窄屏下退化为单列堆叠；功能不丢失。 |
| **可重排** | 用户可临时按角色 / 任务 / 关注度排序；这是客户端偏好，不是领域事实。 |

#### 4.2.3 不应出现的元素

- 不显示"全员大屏"或"团队整体进度百分比"（`architecture.md` §1）。
- 不显示"agent 在线时长"或"任务计数排行"（这是 KPI 化诱惑 — `requirements.md` §7）。
- 不在工位卡片里塞原始日志（`architecture.md` §5.1）。

### 4.3 侧栏（折叠）

按需打开的二级面板：

- **需求版本树**：当前激活需求及历史版本（`REQ-INT-04`）；
- **事件流**：最近 N 条 actor 状态变化与重要领域事件（`REQ-REC-05`）；
- **交付摘要**：未发布需求、已发布需求、剩余风险（`REQ-DEL-01`）；
- **记忆与先例**：当前上下文下被召回的先例 + 来源 + 适用条件（`REQ-MEM-02`）。

### 4.4 模态面板（按需打开）

- **决策详情**：来源、选项、影响、证据、推荐动作（`REQ-ATT-02`）；
- **actor 详情**：当前任务、状态历史、租约、checkpoint、最近产出（`actor-runtime.md` §6）；
- **意图澄清草稿**：草稿与确认动作（`REQ-INT-03`）。

模态不能遮蔽注意力带；决策模态可以同时显示当前其他未解决项的折叠列表。

**写作边界**：意图/原型的撰写本身不在 office UI 内完成。首期由飞书文档/消息承担（详见 §13），office 只承载结构化确认与审批。用户从飞书侧发起意图后，office 内会出现对应的"待澄清"决策项与草稿模态。

## 5. 工位视图（虚拟办公室的承重墙）

### 5.1 工位即 actor 的投影

每个工位卡片是 `actor-runtime.md` 中一个 `ActorConfig` + `ActorState` 的派生视图。卡片至少呈现：

| 字段 | 来源 | 说明 |
|---|---|---|
| **身份** | `ActorConfig.id` + `name` + `role` | 不可省略；用户通过它锚定到 actor。 |
| **当前状态** | `ActorState.kind` | 用视觉语言区分（见 §6）。 |
| **当前任务** | `ActorState.taskId`（当 `running` 时） | 任务 ID + 一句话任务目标。 |
| **需求血缘** | `Task → Requirement.version` | 让用户知道"他在为什么工作"（`REQ-COL-01`）。 |
| **等待原因** | `pause` / `quarantined` / `failed` 的 reason | 必须可点击看到上下文。 |
| **最近活动** | 最新一条 `progress` 或 `state-changed` 事件的时间与摘要 | 不是日志，是"刚刚做了什么"。 |

### 5.2 工位的状态机分群

工位视图按当前状态把卡片分到三个常驻区域。**这不是 UI 分组，是 `ActorState.kind` 的语义映射**（`actor-runtime.md` §3.2、§4）：

| 区域 | 包含的状态 | 含义 |
|---|---|---|
| **正在工作** | `running` | 持有 lease，正在执行任务。 |
| **待命中** | `ready`, `created`, `paused`（无授权原因） | 空闲，等待任务或策略触发。 |
| **需介入** | `failed`, `quarantined`, `paused`（用户授权暂停） | 等人的判断（`actor-runtime.md` §4）。 |

`terminated` 工位不显示在主视图；它进入"已归档"抽屉（默认折叠）。`restarting` 暂时归入"待命中"，但以弱提示标识（避免闪烁 — `NFR-06`）。

### 5.3 工位的稳定位置

- **跨会话稳定**：工位的位置与排序由 server 持久化（用户偏好作为新事实类别，见 §5.5），跨刷新、跨设备保持一致。用户拖动工位会写一条偏好事实，而不是只改客户端状态。
- **状态变化不瞬移**：工位在 `ready` ↔ `running` 之间移动时，**卡片不瞬移**，而是按状态机语义滑动到对应区域。瞬移会丢失因果可解释性（`NFR-02`）。
- **需介入显著标识**：工位在 `failed` / `quarantined` 时用边框 + 图标 + 文字三重表达，不仅靠颜色（可访问性）。
- **身份色与状态色独立**：**身份色**（边框颜色 / 图标）由 `role` 决定；**状态色**（背景 / 边框权重）由 `state_kind` 决定。两者互不干扰（`actor-runtime.md` §3.1）。

### 5.4 工位点击 → 详情

点击工位打开 actor 详情（§4.4），至少包含：

- 当前任务及需求血缘；
- 状态历史（来自 `actor_event`，按 `sequence` 倒序）；
- 租约信息（lease id, until, policy）；
- 最近一次 checkpoint；
- 最近 N 条 `progress` 与 `log`（仅摘要，可展开看原文）；
- 可用命令（见 §8.1）。

详情不是日志浏览器。它把日志重新结构化为"做了什么 / 改变了什么 / 在等什么"。

### 5.5 用户偏好作为新事实类别

工位视图本身是只读派生视图（§3.3），但**用户偏好**（位置、排序、折叠、主题）必须跨会话稳定，否则违反 `REQ-REC-01`（重启后用户体验丢失）。它们必须由 server 持久化。

**这是事实，但不属于领域事实**：用户偏好由注意力视图模块拥有（`architecture.md` §6.1），与领域事实共用同一持久化层（SQLite + WAL — `actor-runtime.md` §8.1），但走独立的表与写入路径。它们不能改写 actor 配置、需求、任务或决策（`architecture.md` §6.3）。任何偏好改变走与领域命令相同的可靠性语义（事务、租约、审计可识别），但**不会触发业务事件**，也不进入审计事实链。

**典型事实项**：

| 事实 | 语义 | 默认值 |
|---|---|---|
| `workstation.position[actorId]` | 工位卡片的视觉位置 | 按 `role` + 创建顺序 |
| `workstation.sort` | 用户选择的排序方式 | 状态机分组（§5.2） |
| `workstation.grouping` | 分群维度（状态 / 角色 / 任务） | 状态 |
| `sidebar.collapsed[*]` | 侧栏各面板折叠状态 | 全部折叠 |
| `decision.inbox.folded` | "搁置"分区是否折叠 | 折叠 |
| `preferences.theme` | 主题 | 跟随系统 |
| `preferences.animations` | 非必要动画开关 | 跟随 `prefers-reduced-motion` |

**约束**：

- 偏好改变不进入决策收件箱（不是阻塞项 — `REQ-ATT-01`）；
- 偏好改变不进入审计事实链（不影响需求/任务/决策语义 — `REQ-REC-05`）；
- 偏好丢失（持久化错误）必须以与领域事实相同的显眼程度提示用户（`REQ-REC-06`），且不允许 UI 在丢失后用随机布局"装作正常"；
- 偏好作用域默认全局；后续若引入多工作空间 / 多项目，偏好必须按工作空间隔离（避免跨项目污染 — `REQ-MEM-05`）。**首期不实现**作用域切换，但 schema 应保留 `workspace` 字段。

## 6. 状态视觉语言

> 本节不规定具体色值，只规定语言规则。具体调色板在视觉规范文档维护。

### 6.1 状态色 = 阻塞语义的函数

| 状态 | 视觉权重 | 说明 |
|---|---|---|
| `ready` / `created` | 中性、低对比 | 不需要人注意。 |
| `running` | 中性 + 进度提示 | 进行中，但不需要人介入。 |
| `paused`（用户暂停） | 中等权重 | 等人的指令；不紧迫。 |
| `paused`（lease 过期 / 策略触发） | 高权重 | 系统在等人。 |
| `failed` | 高权重 + 边框 | 需要人决策。 |
| `quarantined` | 最高权重 + 持续可见 | 不能自动恢复（`actor-runtime.md` §7.1）。 |
| `terminated` | 低对比 | 已归档，不需注意。 |

**约束**：

- 颜色不能是唯一信号。每种状态必须有图标 + 文本标签（`NFR-02`、`REQ-ATT-02`）。
- 红色只用于 `quarantined` 与"未确认的外部副作用"两种语义（`REQ-REC-04`、`architecture.md` §7.7）。
- 颜色不用于表达"actor 重要程度"或"任务紧急度"——避免引入 UI 的隐藏排序（`architecture.md` §3.2）。

### 6.2 运动 = 状态转移的提示

- 状态变化时，工位在区域之间用 ≤ 300ms 滑动。慢于 300ms 会被用户感知为"卡"（`NFR-06`）。
- 进度提示用状态条或脉冲，**不**用动画角色。动画角色暗示 agent 在物理空间内活动，违反 §3.2。
- 用户在偏好设置中可以关闭所有非必要动画；关闭后只剩状态切换的瞬变。

### 6.3 文本 = 因果链

每个工位卡片的"最近活动"用一句话描述：

- 谁（actor）
- 做了什么（动作类型）
- 为什么（任务目标 / 需求版本）
- 接下来会怎样（下一步动作或阻塞原因）

例：`pm-1 完成了需求 R-12 的澄清草案，下一步等你确认验收条件。`
反例：`更新于 14:23`、`agent heartbeat`、`任务进度 +1`。

## 7. 决策收件箱

决策收件箱是体验层的"主入口"，按 `REQ-ATT-01` 至 `REQ-ATT-05` 设计。

### 7.1 决策项的数据来源

决策项由决策管理模块（`architecture.md` §6.1）创建，UI 是它的派生视图。决策项至少包含：

- 来源（哪个需求、任务、actor、事件）；
- 上下文（已收集的证据、相关任务、相关需求版本）；
- 选项（互斥有限个动作，每个动作的影响范围）；
- 阻塞成本（影响多少在途任务）；
- 紧迫性（外部副作用等待、租约临近等）；
- 推荐（如有，必须带依据 + 适用先例 — `REQ-MEM-03`）。

### 7.2 排序

排序由治理层计算，UI 只渲染（`architecture.md` §5.1）。排序依据：

1. 是否存在"未确认的外部副作用"（最高优先级 — `REQ-REC-04`）；
2. 阻塞的在途任务数；
3. 受影响的需求版本是否处于冻结窗口；
4. 紧迫性时间（租约临近、外部 deadline）；
5. 创建时间（兜底 — 防止低优先级长尾遮蔽 — `REQ-ATT-03`）。

排序变化必须有可解释原因；UI 在排序变化时显示"为什么这一条上来了"。

### 7.3 不在收件箱中的事项

- 单纯通知（如"agent 完成了某个非阻塞动作"）不进入收件箱；它们在侧栏事件流。
- 已被自动采用且低风险的先例不进入收件箱（`REQ-MEM-03`）。
- 长时间未读项不进入收件箱；进入"搁置"分区（默认折叠）。

### 7.4 决策动作的影响可见

用户选择一个动作后，UI 必须立刻显示：

- 哪些任务、需求版本、决策、记忆会被改变（`REQ-ATT-05`）；
- 哪些事实事件会被追加（`REQ-REC-05`）；
- 收件箱里其他项的预期变化（部分项可能因此消失）。

**禁止**：执行后不显示影响就关闭模态；这是反 `REQ-ATT-05`。

## 8. 交互边界

### 8.1 UI 可触发的命令

UI 只能调用以下命令集，每个命令都对应领域层的一个明确操作（`architecture.md` §6.3）：

| 动作 | 命令 | 适用对象 | 前置条件 |
|---|---|---|---|
| 确认 / 驳回需求草稿 | 意图治理 | 草稿态意图 | 草稿可见 |
| 回答澄清问题 | 意图治理 | 待澄清意图 | 草稿可见 |
| 查看原型 | 体验层只读 | 原型 | — |
| 提供原型反馈 | 意图治理 | 原型 | 原型可见 |
| 批准 / 拒绝任务执行 | 任务协作 | 任务 | 任务处于可执行状态 |
| 暂停 actor | 任务协作 / 执行适配 | actor | actor 非 `terminated` |
| 恢复 actor | 任务协作 / 执行适配 | actor | actor `paused` |
| 解决决策项 | 决策管理 | 决策项 | 决策项 `open` |
| 触发交付候选 | 交付管理 | 需求版本 | 强制验收已满足 |
| 拒绝交付 | 交付管理 | 交付候选 | — |

### 8.2 UI 不得触发的操作

- 修改 actor 配置（`actor-runtime.md` §3.1 "创建后只读"）；
- 修改决策项的内容或选项；
- 修改需求版本内容；
- 覆盖或删除事件、checkpoint、决策事实（`architecture.md` §9.1）；
- 直接调用外部服务或模型（`architecture.md` §3.2）；
- "自动批量处理所有决策"或"批量应用先例"。

### 8.3 错误反馈

任何命令失败必须显示：

- 失败类别（来自领域错误码 — `actor-runtime.md` §9）；
- 已知原因（来自 server 返回）；
- 建议动作（重试 / 等待 / 升级 / 取消）；
- 不显示原始 stack trace（除非在调试模式下 — `NFR-02`）。

## 9. 实时数据流

### 9.1 订阅模型

UI 通过事件流订阅领域事件。事件至少覆盖：

- `actor.state-changed`（`actor-runtime.md` §5.2）—— 触发工位视图变化；
- 决策项 `created` / `updated` / `resolved`（决策管理）；
- 需求版本 `created` / `updated` / `frozen`（需求管理）；
- 任务 `derived` / `progressed` / `blocked` / `completed`（任务协作）；
- 外部副作用结果 `unknown` / `failed`（`REQ-REC-04`）；
- server `recovery` / `shutdown`（运维信号）。

### 9.2 退避与降级

- 事件流断开时：UI 不假定 server 已死，先用指数退避重连（避免短暂网络抖动触发误判）。
- 重连成功后：UI 不依赖事件流恢复视图，而是主动重新拉取派生视图（领域事实是权威 — `architecture.md` §9.1）。
- 长时间失联：UI 显示"失联中"状态，保留已加载的工位视图（可观察的最后状态），并提示"以 server 为准"。

### 9.3 不可丢失的提示

即便事件流积压，以下两类信号必须即时呈现：

- `quarantined` 出现 / 变化（`actor-runtime.md` §7.1 不可自动恢复）；
- "未确认外部副作用"决策项进入收件箱（`REQ-REC-04`）。

实现层可以为此使用独立通道或优先级队列；本文不规定技术。

## 10. 失败与降级

| 失败 | UI 表现 | 用户仍能做什么 |
|---|---|---|
| server 进程崩溃 | 顶部同步状态变红；工位视图保留最后已知状态并加"快照"标签 | 等待 server 重启（恢复由治理层负责 — `architecture.md` §9.5） |
| 失联但本地可恢复 | 重连后重新拉取，UI 平滑更新 | 与正常时相同 |
| 持久化层错误 | 显著提示；任何写命令按钮禁用（`REQ-REC-06`） | 仅可查看与导出已加载事实 |
| 单个 actor 不可恢复 | 该 actor 工位移到"需介入"，详情页明示恢复策略 | 决策项"重启 / 隔离 / 终止" |
| 事件流过载 | 暂停非关键动画，UI 仍可交互（`NFR-06`） | 与正常时相同 |
| 用户误操作 | 危险动作（解决决策、批准交付、终止 actor）需要二次确认；二次确认展示影响摘要 | 取消或继续 |

## 11. 可访问性与性能预算

### 11.1 可访问性

- 所有状态信号必须有颜色 + 图标 + 文本三重表达；
- 所有命令可纯键盘完成；
- 决策模态打开不夺取全局焦点；
- 动画遵守 `prefers-reduced-motion`；
- 颜色对比度满足 WCAG AA。

### 11.2 性能预算

| 操作 | 预算 | 主要锚点 |
|---|---|---|
| 初次加载到工位视图可见 | ≤ 2s（本地 server） | `NFR-06` |
| 决策收件箱渲染 | ≤ 100ms（100 项内） | `NFR-06`、`REQ-ATT-03` |
| 事件到达 UI 显示 | ≤ 300ms（本地） | `NFR-06` |
| 长任务（agent、检索、构建） | 不得阻塞注意力界面 | `NFR-06` |

性能数字是设计目标；进入实现阶段后以真实负载校验（`architecture.md` §10.4）。

## 13. 不做事项

- **不做聊天界面**：office UI 不模拟 agent 与人的对话，也不承载意图/原型的撰写。**意图与原型的创作上游在飞书**（消息 + 文档）；office 只承载结构化确认、审批与产物索引。产出物是结构化卡片，不是聊天消息。
- **不做实时协作光标**：单用户系统，不引入"他人正在看"的多人化提示（`NFR-09`）。
- **不做 agent 人设化**：不渲染拟人形象、声音、性格设定。这会鼓励用户把 agent 当作有能动性的实体，违反 `architecture.md` §3.2。
- **不做"代理 TM"或全景仪表盘**：不展示业务 KPI、agent 利用率、吞吐曲线（`requirements.md` §7、§6）。
- **不做主题差异化的状态语义**：状态语义在明暗主题下必须一致；主题只影响表层（`architecture.md` §10.3）。
- **不做移动端专属设计**：首期不优化触屏（小尺寸视图是退路，不是目标 — `NFR-09`）。
- **不做内置原型/文档编辑器**：首期不引入富文本、画板、白板等编辑器能力。飞书侧已有等价能力，避免重复建设（`requirements.md` §7）。

## 15. 已决问题（v0.1 评审答复）

| # | 原问题 | 答复 | 落点 |
|---|---|---|---|
| 1 | 工位位置是否需要写入 server？ | **是**，且必须跨刷新、跨设备一致 | §5.3、§5.5（新增用户偏好事实类别） |
| 2 | 决策收件箱超过 N 项是否折叠？ | **是**，折叠进"搁置"分区，并明示"已隐藏 N 项" | §7.3 |
| 3 | 多需求版本并行浏览？ | **首期不支持**；多版本切换进入 v0.2 评估 | §13 隐含 |
| 4 | actor 详情页事件历史深度？ | **默认 20 条**，懒加载更多 | §5.4 |
| 5 | 是否内置写作工具？ | **不做**；飞书承担意图与原型的撰写上游 | §4.4、§13 |

**新增派生设计要求**（来自答复）：

- D-01 **用户偏好表 schema**：必须新增 `user_preference` 表（或等价物），字段至少包括 `key`、`value`、`workspace`、`actor_version`。由注意力视图模块拥有。schema 设计见后续模块设计文档，不在本文件展开。
- D-02 **飞书 → Sinan 的最小接入**：飞书侧意图/原型通过**手工粘贴链接 + 决策项创建**进入 office；不引入 webhook / 自动化读取（避免越界写入 — `NFR-07`）。office 内每个原型/意图条目显示"来源：飞书文档 [标题]"，可点跳转。
- D-03 **收件箱折叠阈值**：建议初值 N = 20。超过时折叠低优先级（按 §7.2 排序末位），并在收件箱底部显示"还有 N 项被折叠到搁置分区"。阈值纳入注意力视图模块配置，可由产品所有者调整。
- D-04 **actor 详情历史分页**：默认 `limit=20`，`since=sequence` 游标分页；点击"加载更早事件"触发增量拉取。
- D-05 **最小化拟人化例外**（v0.3 起，**显式规范偏差**）：在 §3.2 / §6.2 / §13 之外允许一项**有界破例**，使办公室隐喻对单人产品所有者具备可感的"现场感"，而不只是状态机分群。
  - **范围**：仅在工位卡片顶部渲染一个 64×64 的几何风格 SVG 头像（圆头 + 圆肩 + 角色小道具），不画面部特征、不画手指、不画光影细节；不引入 3D / 透视变换。
  - **角色道具**（**唯一**用来区分身份的非文字信号，必须与 §5.3 的身份色 + 文字姓名**三重一致**）：PM 记事本、Designer 画笔、Developer 笔记本、QA 放大镜、DevOps 扳手。
  - **动画**（必须尊重 `prefers-reduced-motion` 与 §5.5 `preferences.animations` 偏好；默认随系统）：
    - `running`：屏幕上的"打字"光标闪烁 + 偶发键入点点（仅动画小道具，**不**动画头像本身）；
    - `ready` / `created`：极慢的呼吸透明度（0.95↔1.0，4s 一轮，< 0.5px 视觉位移）；
    - `paused`：头像静止，小道具上的暂停符号淡入；
    - `restarting`：头像静止，小道具上的进度环旋转；
    - `failed` / `quarantined`：头像静止，外圈警示环脉冲（不动画头像本身）；
    - `terminated` / `initializing`：无动画，整张卡片降饱和度。
  - **未变条款**：头像不承载状态语义（状态仍由徽章 + 色带 + 文字表达，§6.1）；头像不暗示 agent 情绪或意图（§3.2）；动画不暗示 agent 在物理空间移动（§3.2）；动画可一键关闭（§6.2）。
  - **可访问性**：所有动画使用 `motion-safe:` 变体（Tailwind）；关闭动画后视觉仍完整可读；头像 `aria-hidden="true"`，身份信息靠相邻的姓名 + 角色文字。
  - **影响**：违反 §13「不做 agent 人设化」中"不渲染拟人形象"的部分条款；以本派生设计要求 D-05 替代之。v0.4 评审时复核，必要时回退。
